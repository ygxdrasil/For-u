# n8n workflow assistant

Designs, builds, validates, tests and repairs n8n workflows. It does not talk —
replies are text on a screen. There is no text-to-speech, no wake word and no
ambient listening anywhere in this codebase.

## The shape

```
core/run.js          THE pipeline: run(input, hooks) → result
core/tools.js        the tool registry — built in exactly ONE place
api/chat.js          browser, server-sent events
api/agent.js         token-authed JSON in / JSON out
api/sweep.js         scheduled failure check
api/health.js        which build is actually live
api/tokens.js        mint / retire tokens
```

`core/run.js` knows nothing about HTTP, browsers or rendering. Every entry point
calls it. What varies between callers is only how the work is watched, passed in
as `hooks`. A test fails the build if any entry point is ever offered a
different set of tools.

## The headless endpoint

This is the seam a voice assistant plugs into — it sends the sentence and reads
the answer aloud itself.

```bash
curl -X POST https://<host>/api/agent \
  -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"is anything broken?"}'
```

```json
{ "ok": true, "status": "ok", "reply": "…", "steps": [...], "spend": {...} }
```

## How it avoids inventing things

`vendor/catalog.json` and `vendor/schemas/` are generated from the
`node-definitions` tree that n8n itself ships inside `n8n-nodes-base` — 517
nodes, 3,582 operations, machine-generated by n8n's own build. The model cannot
see a parameter name until it calls `get_node_schema`.

Validation runs in three layers, because none of them is sufficient alone:

| layer | catches | misses |
| --- | --- | --- |
| n8n's own Zod schemas | bad enum values, wrong types, bad discriminators | **invented parameter names** (zod strips unknown keys), unknown node types (fails open) |
| the catalog | node types that don't exist, parameter names that don't exist, missing required params, guessed picker values | type-level detail |
| the graph | no trigger, unreachable nodes, connections to missing nodes, cycles | — |

Those gaps were measured against the real SDK, not assumed. `validateNodeConfig`
returns `valid: true` for `{ channel: '#general' }` on a Slack node.

## Regenerating the node index

The node packages are ~1.7GB of transitive dependencies, so they are
deliberately not dependencies of this app. Install them only when regenerating:

```powershell
npm install --no-save n8n-nodes-base@2.15.1 "@n8n/n8n-nodes-langchain@2.32.4"
node scripts/build-node-index.mjs
```

Pin the versions to whatever your n8n instance runs. The catalog records which
versions it was built from, and the assistant reports the mismatch rather than
claiming certainty when they differ.

## Tests

```powershell
node --test tests/*.test.js    # 32 tests
node scripts/selftest.mjs      # whole pipeline against stubbed n8n and model
```

The self-test drives a full build — search, schema, validate, save, dry run —
and asserts the assistant tells the truth in each of the four outcomes: worked,
worked-but-invisible, could-not-confirm, and genuinely failed.

Every script is invoked as `node <path>`, never `npx` and never a bare CLI name,
because `.cmd`/`.bat` shims are blocked by group policy on the target machine.

## Configuration

Keys can be pasted into the web UI (kept in that browser's localStorage) or set
as server environment variables. Server env is required for `/api/sweep` and for
`/api/agent` to work without a browser.

| variable | what for |
| --- | --- |
| `DATABASE_URL` | **required.** Postgres (Neon free tier). Holds the password, your encrypted keys, snapshots and the spend meter |
| `MASTER_KEY` | recommended. Encrypts stored API keys with a key held outside the database |
| `AGENT_TOKEN` | bootstrap token for `/api/agent`; also the admin credential for `/api/tokens` |
| `GEMINI_API_KEY` | optional — the Settings page is the normal way to set this |
| `N8N_BASE_URL`, `N8N_API_KEY` | optional, same |
| `MONTHLY_USD_CAP` | default 8 |
| `ALLOW_MEMORY_AUTH` | dev only. Lets the password flow run without a database. Never set in production |

### Why `vercel.json` has an `ignoreCommand`

`git diff --quiet HEAD^ HEAD -- .` builds only when something in `assistant/`
changed. Two projects deploy from this one repo — Jason from here and Selena
from `selena/` — so every push used to build both, and two builds per push
exhausted the Hobby plan's daily deployment limit in an afternoon. Vercel skips
the build when the command exits 0, which is what `git diff --quiet` does when
nothing here moved.

This explanation is in the README rather than in `vercel.json`, because
**Vercel validates `vercel.json` against a closed schema before the build
starts**. An unknown top-level key does not warn and is not ignored: the
deployment fails with `should NOT have additional property`, writes no build
logs because no build begins, and cannot be redeployed from the dashboard.
A `_comment_` key added to explain this very setting took both projects down
for a day. `selena/tests/structure.test.js` checks both files for it now.

## The front door

The site is on a public URL and, once configured, holds an n8n API key with
full read/write on every workflow. So the first screen is a password:

- **First run** claims the instance by setting the password. It only works while
  no password exists, so it cannot double as a reset.
- Passwords are **scrypt** hashed and salted, compared in constant time.
- Sessions are **signed HttpOnly cookies** — not readable from JavaScript, and
  a tampered payload fails the signature check.
- Stored API keys are **AES-256-GCM encrypted**. `GET /api/settings` returns
  only whether each key is set plus its last four characters; the values never
  travel back to the browser.

Setting a password is **refused without a database**, deliberately. Serverless
instances come and go, so a password in one instance's memory would vanish when
another served a request and lock you out at random. Better to say why than to
half-work.

To reset a forgotten password: clear the `auth:owner` row from the `app_kv`
table.

### Getting a database

Either route gives you a `DATABASE_URL` on the free tier:

- **Vercel** → project → Storage → create a Neon Postgres database. It sets
  `DATABASE_URL` for you.
- **neon.tech** → new project → copy the pooled connection string → add it as a
  Vercel environment variable.

Tables are created on first use; there is no migration step to forget.

## Money

Prices are per-model, read from Google's published pricing on 2026-07-31 and
recorded in `core/meter.js`. An unpriced model raises a loud error rather than
billing at a fallback rate, because a fallback rate makes the meter wrong in
both directions. The spend cap is checked **before** each request.

Thinking tokens bill at the output rate. `assertThinkingBudgets()` refuses to
start if a tier's thinking budget reaches its output ceiling, because that
returns an empty string from a request that looks entirely healthy.

## What it will not do

- Delete anything. There is no delete tool and no `DELETE` request in the n8n
  client. Retiring means deactivate + archive; updates snapshot first.
- Activate a workflow that can send things, without explicit approval.
- Claim something worked without an execution record read back.
- Report "it isn't working" when it means "I couldn't check".
